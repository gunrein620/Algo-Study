# 크기가 작은 부분문자열 — 시작 위치와 자르는 길이

[전체 목차](../README.md) · [오답노트 목차](README.md) · [복습 목차](../04-복습노트/README.md) · [슬라이싱 교과서](../01-파이썬-도구/06-문법/slicing.md) · [range](../01-파이썬-도구/04-반복과-변환/range.md)

- 기록일: 2026-09-25
- [문제 원문](https://school.programmers.co.kr/learn/courses/30/lessons/147355): t에서 p와 같은 길이의 연속 부분문자열을 모두 검사하고, 숫자 값이 p 이하인 것의 개수를 반환한다.
- 조건: `1 ≤ len(p) ≤ 18`, `len(p) ≤ len(t) ≤ 10,000`. t와 p는 숫자 문자열이며 0으로 시작하지 않는다. **중간에서 자른 문자열은 0으로 시작할 수 있다.**
- 내 상태: 처음부터 자른 문자열을 숫자로 비교하는 접근은 맞았다. 설명 후 올바른 코드를 작성했고, 반복 범위와 슬라이싱을 핵심으로 짚었다. 제출 통과·독립 재풀이는 미확인.

## 답을 가리고 먼저 생각하기

1. t의 길이가 7이고 자를 길이가 3이면 마지막 시작 위치는 어디인가?
2. 마지막 시작 위치와 반복 횟수는 왜 1만큼 다른가?
3. `t[i:i + length]`는 몇 글자를 자르는가? 끝 위치는 포함하는가?
4. `t[i:i + length]`만 한 줄에 쓰면 temp에 저장되는가?
5. `int("02")`는 오류인가, 숫자 2인가?

<details>
<summary>해설 1 — 내가 수정한 정답 풀이와 모범답안</summary>

## 내가 수정한 풀이

```python
def solution(t, p):
    length = len(p)
    target = int(p)
    answer = 0

    for i in range(len(t) - length + 1):
        temp = t[i:i + length]
        if target >= int(temp):
            answer += 1

    return answer

print(solution("3141592", "271"))   # 2
print(solution("500220839878", "7"))  # 8
print(solution("10203", "15"))     # 3
```

이 풀이는 맞다. temp를 따로 두면 잘라낸 문자열을 확인하기 쉽다.
`target >= int(temp)`와 `int(temp) <= target`은 같은 조건이다.

## 모범답안 — 같은 풀이에서 중간 변수만 생략

```python
def solution(t, p):
    length = len(p)
    target = int(p)
    answer = 0

    for i in range(len(t) - length + 1):
        if int(t[i:i + length]) <= target:
            answer += 1

    return answer

print(solution("3141592", "271"))  # 2
```

새로운 함수가 필요한 문제가 아니다. **시작 위치를 순회 → 일정 길이로 자르기 → 숫자로 비교 → 개수 누적**을 연결한다.

<details>
<summary>해설 2 — 왜 range(len(t) - length + 1)인가?</summary>

## 먼저 마지막 조각을 놓아 보기

`t = "3141592"`, `length = 3`이다.

| 인덱스 | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 문자 | 3 | 1 | 4 | 1 | 5 | 9 | 2 |

끝에 딱 맞는 마지막 조각은 `"592"`이고, 시작 위치는 4다.

```text
전체 길이 7 - 자를 길이 3 = 마지막 시작 위치 4
가능한 시작 위치: 0, 1, 2, 3, 4
range는 끝을 제외하므로 range(5)
따라서 range(7 - 3 + 1)
```

**`len(t) - length`는 마지막 시작 위치다. 여기에 1을 더하는 것은 range에 그 마지막 위치까지 포함시키기 위해서다.**

## 슬라이싱의 끝도 제외한다

`t[i:i + length]`의 시작은 i, 끝은 i + length다. 끝을 제외하므로 가져오는 글자 수는 `(i + length) - i = length`다.

| i | 슬라이싱 | 자른 문자열 | 숫자 변환 | 271 이하? |
| --- | --- | --- | --- | --- |
| 0 | `t[0:3]` | `"314"` | 314 | 아니오 |
| 1 | `t[1:4]` | `"141"` | 141 | 예 |
| 2 | `t[2:5]` | `"415"` | 415 | 아니오 |
| 3 | `t[3:6]` | `"159"` | 159 | 예 |
| 4 | `t[4:7]` | `"592"` | 592 | 아니오 |

조각들은 서로 겹쳐도 된다. 시작 위치를 한 칸씩 옮겨 모든 후보를 확인한다.

만약 `range(len(t))`로 끝까지 돌면 `t[5:8]`은 `"92"`, `t[6:9]`는 `"2"`가 된다.
슬라이싱은 범위를 넘겨도 오류 대신 있는 부분만 반환한다. 그래서 **길이가 부족한 조각을 세지 않도록 반복 범위를 제한해야 한다.**

## 숫자 변환은 처음 생각이 맞았다

```python
temp = "02"
target = int("15")
print(int(temp))            # 2
print(int(temp) <= target)  # True
```

문자열을 자를 때는 문자의 개수를 기준으로 삼고, 비교할 때 int로 바꾼다.
p는 반복 중 변하지 않으므로 `target = int(p)`를 반복문 앞에 둔다.

</details>

<details>
<summary>해설 3 — 처음 시도에서 무엇이 잘못됐나?</summary>

아래는 처음 작성한 코드다. 오류를 복습하기 위한 기록이며 실행용 정답이 아니다.

```text
def solution(t, p):
    answer = 0
    for i in len(t):
        temp = ''
        t[i:i+3]

        if int(p) >= int(temp):
            answer += 1

    return answer
```

| 처음 쓴 표현 | 문제 | 수정 |
| --- | --- | --- |
| `for i in len(t)` | len(t)는 정수이므로 순회 불가 | 시작 위치를 range로 만든다 |
| `temp = ''` 뒤에 `t[i:i+3]` | 잘라낸 값을 저장하지 않아 temp는 여전히 빈 문자열 | `temp = t[i:i + length]` |
| `i + 3` | 예제의 길이 3을 고정함 | p의 길이인 length 사용 |
| `int(temp)` | 빈 문자열이면 ValueError | 자른 숫자 문자열을 먼저 저장 |

`int(p)`로 비교하려던 생각 자체는 맞았다. 먼저 순회 오류가 발생하며, 순회만 고쳐도 빈 문자열 변환 오류가 남는다.

</details>

## 5분 복습 — 범위를 직접 적기

| t | p | 마지막 시작 위치 | range(...) | 검사할 조각들 |
| --- | --- | --- | --- | --- |
| `"10203"` | `"15"` | | | |
| `"1234"` | `"1234"` | | | |
| `"505"` | `"5"` | | | |

추가 질문: 첫 행에서 `+ 1`을 빼면 어떤 조각을 놓치는가?

<details>
<summary>복습 정답</summary>

| t | 마지막 시작 위치 | 반복 범위 | 조각들 | 반환값 |
| --- | --- | --- | --- | --- |
| `"10203"` | 3 | `range(4)` | `"10", "02", "20", "03"` | 3 |
| `"1234"` | 0 | `range(1)` | `"1234"` | 1 |
| `"505"` | 2 | `range(3)` | `"5", "0", "5"` | 3 |

첫 행에서 +1을 빼면 range(3)이 되어 i=3의 `"03"`을 놓친다. 값이 같은 조각도 서로 다른 위치에서 나왔다면 각각 센다.

</details>

## 이번에 가져갈 것

1. **마지막 시작 위치:** 전체 길이 - 자를 길이. range에서는 여기에 1을 더한다.
2. **일정 길이 추출:** `t[i:i + length]`. 자른 값을 쓰려면 저장하거나 다른 식에 바로 넣는다.
3. **숫자로 비교:** `int(temp) <= target`. 앞에 0이 붙은 조각도 숫자로 변환할 수 있다.

<details>
<summary>복잡도와 경계 조건</summary>

전체 길이를 N, p의 길이를 L이라 하면 N-L+1개의 조각을 검사한다. 각 조각의 슬라이싱과 제한된 길이의 숫자 변환을 고려한 시간은 O((N-L+1) × L), 추가 공간은 O(L)이다. 이 문제에서는 L이 최대 18이다.

- 두 길이가 같으면 시작 위치 0에서 한 번 검사한다.
- p가 한 글자면 모든 문자를 하나씩 검사한다.
- 숫자 값이 같을 때도 세므로 `<`가 아닌 `<=`를 쓴다.

</details>
